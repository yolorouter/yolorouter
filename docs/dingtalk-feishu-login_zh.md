# 钉钉 / 飞书登录接入指南

[English](dingtalk-feishu-login.md)

YoloRouter 成员可以用工作用的钉钉或飞书账号登录。首次登录成功即自动创建成员账号——无需邀请、无需预建。账号身份取自提供方的稳定用户标识（`unionId` / `union_id`），因此上游改名不影响登录，两个显示名相同的人也是两个独立账号。

两种登录的接入姿势相同：在提供方开放平台建应用 → 登记路由的回调地址 → 在路由管理界面用内置预设建 Provider。

## 前置条件

- `configs/config.yaml` 里的 `server.external_url` 必须设置成浏览器实际访问本实例的地址（协议、主机、端口都要对）。所有回调地址都由它推导，两家提供方都是逐字符精确匹配。
- 路由管理后台的访问权限（系统设置 → 登录方式）。
- 公司钉钉 / 飞书开发者后台的管理权限。

每个 Provider 的精确回调地址显示在路由的 Provider 表单里——直接用复制按钮，别手打。

## 飞书

1. **建应用。** 在 [open.feishu.cn](https://open.feishu.cn) 开发者后台创建**企业自建应用**。「凭证与基础信息」页复制 **App ID** 和 **App Secret**。
2. **登记重定向 URL。** 「安全设置」→ 重定向 URL，添加路由 Provider 表单里显示的回调地址：`http(s)://你的主机/oauth/callback/feishu`。精确匹配，请用复制按钮。
3. **（可选）用户邮箱。** 只有应用开通了「获取用户邮箱信息」（`contact:user.email:readonly`）权限才会返回用户邮箱；不开的话自动创建的账号邮箱为空，登录不受影响。注意飞书官方标注邮箱是管理员导入、未经用户本人验证的——这正是 YoloRouter 从不用邮箱做身份的原因。
4. **发布应用版本**，租户内成员才能使用。
5. **在路由建 Provider。** 管理后台 → 登录方式 → 新增 → 配置方式选**飞书** → 粘贴 App ID / App Secret → 保存。其余（端点、令牌协议、字段映射）预设已全部填好。
6. **测试。** 退出登录 → 登录页点飞书按钮 → 同意授权 → 应以新成员身份进入控制台。

**谁能登录：** 该应用所属飞书租户内的成员。应用就是门禁——想限制到部分组织，在飞书管理后台收窄应用的可用范围即可。

## 钉钉

1. **建应用。** 在 [open.dingtalk.com](https://open.dingtalk.com) → 应用开发 → **企业内部应用**（如 H5 微应用）。「凭证与基础信息」页复制 **AppKey** 和 **AppSecret**。
2. **登记重定向 URL。** 应用 →「安全设置」→ **重定向URL（回调域名）**——添加路由表单里的完整 URL（含协议和端口）：`http(s)://你的主机:端口/oauth/callback/dingtalk`。钉钉逐字符精确匹配。
3. **开通 userinfo 权限（必做）。** 应用 →「权限管理」→ 搜索「个人信息」→ 申请**「获取用户通讯录个人信息」**。缺了它登录会在最后一步以 403 失败。
4. **发布应用版本。** 重定向 URL 和权限的变更都要发布后才生效。
5. **在路由建 Provider。** 登录方式 → 新增 → 配置方式选**钉钉** → 粘贴 AppKey / AppSecret → 保存。预设自带扫码登录端点、JSON 换令牌协议、钉钉自定义 userinfo 头、PKCE 关闭——高级区不用动。
6. **测试。** 登录页 → 钉钉按钮 → `login.dingtalk.com` 出扫码页 → 手机钉钉扫码并在确认页同意 → 首次登录成功即建号。

**谁能登录：** 应用所属钉钉组织内、且在应用可见范围内的成员。

## 说明

- **用户名与显示名。** 本地用户名由资料名派生并折叠为小写字母、数字、连字符（纯中文名会回退成 `<provider>-user`，冲突自动加后缀）；显示名保留原文。身份不依赖二者——是提供方的 union id。
- **账号永不合并。** 一个提供方账号对应一个本地账号。同一个人分别用飞书和钉钉登录就是两个账号，属设计行为；没有按姓名或邮箱的自动关联。
- **手动配置。** 预设只是预填了值的普通 Provider。「手动配置」方式暴露同样的协议旋钮（令牌请求编码、JSON 字段命名、自定义 userinfo 鉴权头、PKCE 开关、额外授权参数），可接任意其他身份提供方。

## 排错

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 飞书授权页报「email openid profile 有误」 | Provider 的授权范围（scopes）里带了飞书不认的 OIDC 风格 scope 名 | 编辑该 Provider，把**授权范围**清空保存 |
| 飞书同意后登录失败，路由日志见 "PKCE code challenge failed" | 手动混搭了飞书不同代际的授权/换令牌端点 | 照用预设的端点组合 |
| 钉钉同意后登录失败，路由日志见 `status 403` | 应用缺「获取用户通讯录个人信息」权限 | 权限管理里开通并重新发布应用 |
| 钉钉扫码页提示无权限或扫码后无反应 | 回调地址不匹配（协议/主机/端口需完全一致），或变更未发布 | 从路由表单重新复制 URL；发布应用版本 |
| 账号邮箱为空 | 未开通提供方的邮箱敏感字段权限，属预期 | 可选：按需开通；已有账号不会回填 |

登录失败时，路由服务端日志会带提供方在换令牌 / 取用户信息阶段返回的原始错误体——搜 `oauth: callback failed`。
